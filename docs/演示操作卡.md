# 演示操作卡

适用：车端项目 `~/patrol-prototype`，工作台8765、采集控制8766都运行在车上；虚拟机、Windows后台不再是演示依赖。

## 启动

已安装orin用户的开机自启；保持热点开启，上电后等待日期校准和模型加载（通常1–3分钟，校时最多等待5分钟），手机重新载入网页。开机不会自动使能或恢复旧路线。顶部“手机独立测试操作卡”可展开，现场电脑可离线。
下列SSH命令用于开发/故障恢复，正常手机测试不必使用。移除自启：`python3 scripts/install_boot_start.py --remove`，会保留其他cron任务。

1. 小车供电，手机热点保持开启；手机、电脑与小车同网。换热点后车屏执行`hostname -I`，使用无线网卡IP，忽略Docker的172.17.0.1。
2. Windows PowerShell连接（IP按实际替换）：

```powershell
ssh orin@10.71.225.243
```

3. 以下在SSH后的`orin@ubuntu`终端执行。查看画面/开发、无需驱动车辆时：

```sh
cd ~/patrol-prototype
sh start_car_workbench.sh
```

现场有人监护、准备驾驶时，启动硬件模式：

```sh
cd ~/patrol-prototype
sh start_car_workbench.sh --hardware
```

该参数允许串口写入，但不会自动使能、行驶、恢复旧路线；原有最大动力与停车阈值保留。默认无参数关闭硬件写入。不要用遗留`start_hw_ground.sh`：其旧参数会覆盖当前配置。

4. 手机打开`http://<车IP>:8765/`，使用`.local-access/登录信息.txt`中的账号密码；登录异常先重新载入。此处是http，不是https。

## 现场巡检

- 先看实时画面是否更新、队列是否补传、测距显示和具体停止原因。重启后重新确认检查点A/B/C。
- 点“使能低速控制”，按住方向行驶、松手停止。前进最大0.15、倒车最大0.08、转向±300；软件停止不替代现场断驱动电源的手段。
- 底盘反馈未恢复可在停车、路线idle、未使能时点“重连底盘”，等数秒看状态；该按钮不会使能。重连不保证修复所有串口故障，仍失败就整车重启后等自启。
- 回放时手机控制页保持前台，100ms续监护；超出0.5秒未收到监护时车端中止，锁屏、切页也会停车。电脑无需联网。零动力监护失联/正常结束已测，真实运动中失联仍需现场验收。
- 当前前方阈值25cm。有效近障会停车；监护模式允许无回波操作，不能据此认定前方安全。故障码7、断线、过期仍停车。停车后检查原因再重新使能，不自动恢复。
- 新场地从起点录制新路线，命名“场地-日期-序号”，手动走短路线后结束保存；回放前回到相同起点和朝向、清空路线内人员。当前为指令时间轴回放，含倒车；没有定位纠偏，不保证重复轨迹精度。严禁盲跑示例路线或其他场地路线。
- 垃圾只上报；障碍停车后由人处理，不自动绕行。夜间停车拍照并提供白光补光。
- 事件→AI分析→人工确认→创建任务→Android接单与处理照片→提交→管理员关闭。详见[云端识图](云端识图.md)。

## 故障与停止

- 控制页面消失、心跳超时、传感器故障：现场确认已停，再检查网页原因和日志；不要反复点使能掩盖故障。
- 停止巡检：先点“停止路线”，再点“停止并锁定”。电池异常时停止使用并按厂家方法处理，不强充欠压电池。
- SSH检查日志（不打印密钥）：

```sh
cd ~/patrol-prototype
tail -n 60 runtime/robot.log
tail -n 60 runtime/server.log
```

- 定位检查只读命令：`bash scripts/check_localization.sh`。目前MID360网口无物理链路，尚未建图；需恢复雷达供电/连接后重验，不拆封闭外壳排线。

## 尚未验收

服务重启及真实整车重上电自启已验证：未使能、零动力、新鲜轮速0、相机恢复，任务和AI结果保留。实际热点断开、动态刹停距离、三种地面、户外夜巡、定位导航、场景录像仍未验收。勿将现有静态/室内证据标记为这些项目通过。
