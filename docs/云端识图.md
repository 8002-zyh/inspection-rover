# 云端识图与离线恢复

工作台和采集服务均在车上。手机、电脑连接同一个热点，打开 `http://<车IP>:8765/`。
当前使用 DeepSeek 官方 `deepseek-flash` 视觉接口。AI只审核图片，不输出车辆控制指令。

## 操作

1. 停车，确认补光、相机朝向和现场目标。选择A/B/C后点击“确认当前检查点”；服务重启后需重新确认。
2. 点击“保存现场照片”，进入“异常与采样”。找到正确时间、检查点的图片，点击“AI分析此图”。
3. 稍后刷新，查看场景、判断、图像依据、处理建议和限制。结果始终需要人工确认。
4. 确认异常后“创建处理任务”。Android“处理任务”中接单、上传处理后照片并写说明、提交；管理员复核关闭或退回。

正常树草不是异常；室内地面瓶子不能直接证明林地垃圾。单幅图像不能判断精确距离、完整可通行范围、病虫害确诊或可靠自主避障。

## 配置与服务

在车端项目目录的 `.local-access/vision-api.json` 配置下列字段，真实密钥只保存在该私密文件：

```json
{"base_url":"https://api.deepseek.com","model":"deepseek-flash","api_key":"替换为实际密钥"}
```

修改后重启后台以生效。可通过环境变量 `PATROL_VISION_CONFIG` 指定其他私密配置路径。
不要提交此文件、登录文件、数据库、现场照片或私钥。官方文档：[视觉](https://api-docs.deepseek.com/guides/vision/)、[JSON](https://api-docs.deepseek.com/guides/json_mode/)。

## 失败行为

- 图片先本地持久化，采集上传队列与AI分析队列分别保存。互联网不可用时，本地网页、任务与采集可继续；热点本身断开时手机无法访问车端网页，失去控制心跳会停车。
- AI只由操作员点击触发，同一event_id待处理/处理中/成功时再次请求不新增作业。网络错误、429和服务端5xx最多尝试3次；耗尽后显示失败，人工点击可重试。
- 模型偶尔可能返回不完整JSON，此时显示分析失败，不展示伪造结果。2026-11-01实测遇到一次此类错误，人工重试成功。
- 进程启动会恢复未完成作业。云请求已发出但结果落盘前进程死亡时，重试可能产生第二次API计费；不保证跨崩溃恰好计费一次。
- 不是每秒照片都上传云模型；只有人工选中的图片发送，避免连续采样产生无界费用。
